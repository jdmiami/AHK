## ADDED Requirements

### Requirement: Single brand source

The web app MUST expose one brand module (`apps/web/src/lib/brand.ts`) providing the short name `AHK`, the full name `Artist House Karaoke`, a localized tagline key, and the canonical public URL. Page metadata, structured data, the PWA manifest, `llms.txt`, and any component that renders the product name MUST read from this module or from locale strings that interpolate it.

#### Scenario: Name appears in metadata

- **WHEN** the root layout builds metadata for any locale
- **THEN** `title.default`, `applicationName`, `openGraph.siteName`, and structured-data `name` contain `AHK` and the full name comes from the brand module

### Requirement: No upstream product name in user-facing surfaces

Compiled locale objects and user-rendered string literals under `apps/web/src` MUST NOT contain the upstream product name (case-insensitive). Internal identifiers (`@vkara/*` package names, `VKARA_*` env vars, `--vkara-*` CSS variables, Redis keys, Docker image/service names) are exempt and MUST remain unchanged.

#### Scenario: Locale guard test

- **WHEN** the locale parity test runs
- **THEN** it fails if any value in `en` or `es` matches `/vkara/i`

#### Scenario: Internal identifiers untouched

- **WHEN** the rebrand change is complete
- **THEN** workspace package names still start with `@vkara/` and env var names still start with `VKARA_`

### Requirement: Neon-lounge theme tokens

The app MUST define dark (default) and light themes through the existing shadcn HSL token names in `globals.css`, with primary magenta `#FF2DAA`, secondary cyan `#22E6FF`, accent violet `#7C5CFF`, background `#07060B` in dark mode, and darkened accents in light mode so body text and button labels meet WCAG AA contrast. Glow effects MUST use `--ahk-glow-primary` / `--ahk-glow-secondary` box-shadow tokens.

#### Scenario: Default appearance

- **WHEN** a new visitor opens the app with no stored appearance preference
- **THEN** the dark theme renders

#### Scenario: TV route still downlevels

- **WHEN** `bun run build` executes `tv-downlevel` and `tv-verify`
- **THEN** both succeed and the `/tv` route uses no `backdrop-filter`, `color-mix()`, `oklch()`, `:has()`, or container queries

### Requirement: SVG-derived icon set

Brand raster assets (`public/icons/*`, `favicon.ico`, `og-image.png`) MUST be generated by `apps/web/scripts/generate-pwa-icons.mjs` from SVG sources in `apps/web/brand/` (`ahk-mark.svg`, `ahk-mark-flat.svg`, `ahk-lockup.svg`). Upstream PNG sources and upstream icon files MUST be removed.

#### Scenario: Regenerate icons

- **WHEN** `bun run generate:pwa-icons` runs in `apps/web`
- **THEN** it writes icon-32, icon-192, icon-512, maskable-icon-512, apple-touch-icon, favicon.ico, and a 1200×630 og-image from the SVG sources

### Requirement: Fork carries no upstream deployment identity

The repository MUST NOT contain upstream Sentry DSNs, funding links, Expo/EAS project ids, Tizen app ids, or upstream Docker Hub owner names. The Docker publish workflow MUST read the image owner from a repository variable and skip pushing when it is unset.

#### Scenario: CI without Docker credentials

- **WHEN** the publish workflow runs in a fork with no `DOCKERHUB_OWNER` variable
- **THEN** the build job succeeds and the push step is skipped
